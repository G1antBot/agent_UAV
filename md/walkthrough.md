# 毕业设计：混合架构控制系统消融实验指南

我们已经成功将之前“规则快照版”里的高频规则分流逻辑合并到了当前的主代码 `OpenAI_api_Mavlink_Agent.py` 中。
现在，你的系统不仅拥有大模型的泛化能力，还拥有了底层硬规则的高速实时性，并且我们可以**通过一个开关一键切换它们**，用来生成论文数据。

## ✨ 核心更新内容

1. **Config.json 新增开关**：
   引入了 `agent_config.enable_hard_rule_routing`。
   * 设置为 `true` 时：开启混合架构（本文提出的最佳方案）。
   * 设置为 `false` 时：关闭硬规则分流，所有指令全部发给大模型解析（Baseline 对照组）。

2. **_handle_hard_rules 函数升级**：
   * **最高安全规则**：“退出程序”和“急停”是无论开关是真是假都会立刻生效的，以防止你在跑纯 LLM Baseline 的时候因为网络延迟而炸机。
   * **分流规则**：现在的代码能够一瞬间识别出所有的方向位移、转向、搜索（quick/all）、靠近、朝向命令。如果命中了这些词，直接在一秒钟内走本地模板，系统不再经过慢吞吞的 LLM 生成。

## 📊 如何使用它来进行你的对比实验？

这是你接下来收集论文数据的“傻瓜式”流程：

### 第一步：跑你的对照组 (Baseline - 纯 LLM 版)
1. 打开 `ServerFile/Config.json`。
2. 将 `"enable_hard_rule_routing"` 改为 `false`。
3. 运行你的程序（比如在仿真里跑）。
4. 在控制台输入基础指令，例如：`向左转 45 度`。
5. **预期现象**：你会看到日志打印出 `交由LLM处理`，然后系统会卡顿几秒钟等待 LLM 生成 Python 代码，最后执行转向。
6. *这为你提供了反面案例：用来证明纯 LLM 方案存在严重的响应延迟。*

### 第二步：跑你的实验组 (Proposed Method - 混合架构版)
1. 打开 `ServerFile/Config.json`。
2. 将 `"enable_hard_rule_routing"` 改为 `true`。
3. 再次运行程序。
4. 同样输入：`向左转 45 度`。
5. **预期现象**：你会看到日志瞬间打印 `[TURN] dir=向左转 deg=45.00`，系统跳过 LLM 瞬间完成转向。
6. *这为你提供了正面案例：用来证明你提出的混合架构在不牺牲智能性的情况下，大幅降低了基础控制的时延。*
