## 📄 文献核心内容提炼

### 1. Agent as Cerebrum, Controller as Cerebellum ([arXiv:2311.15033](https://arxiv.org/abs/2311.15033))
> **重点：这篇论文的架构和你的项目几乎一模一样！是你毕设最重要的“核心对标论文”。**

*   **研究痛点 (解决什么问题)**：传统的基于 LLM 的无人机控制系统试图让 LLM 掌握所有的低级飞控信号，导致**推理延迟过高、系统极不稳定**。
*   **提出的方案**：“大脑（Agent/LLM）负责高级认知和任务拆解” + “小脑（Controller/硬规则）负责底层运动控制和避障”。（这完全对应了你代码里的 `OpenAI_api_Mavlink_Agent.py` 和 `Communication_Mavlink.py`！）
*   **对比实验 (Baselines)**：
    *   纯大模型端到端控制 (LLM-only)
    *   本论文的“大脑+小脑”混合控制 (Cerebrum-Cerebellum)
*   **评估指标 (Metrics)**：
    *   **Success Rate (任务成功率)**：能否完成寻找并靠近目标。
    *   **Response Latency (响应延迟)**：比较混合架构下，无需 LLM 介入的低级动作（如急停、底层逼近）节约了多少时间。

### 2. Vision-and-Language Navigation for UAVs: Survey ([arXiv:2604.13654](https://arxiv.org/abs/2604.13654))
> **重点：这是用来写你论文“文献综述”和“引言”的最佳材料。**

*   **研究痛点 (解决什么问题)**：无人机在三维空间中执行人类自然语言指令（VLN）存在巨大的语义鸿沟和环境复杂性。
*   **发展趋势**：从传统的“关键词匹配+规则”正在全面转向“多模态大模型 (MLLM) 驱动”。
*   **评估指标 (Metrics) 标准化建议**：
    *   **SPL (Success weighted by Path Length)**：不仅要求成功走到目标，还要求**路径越短越好**。（如果你的仿真能拿到轨迹长度，强烈建议加入这个指标）。
    *   **Navigation Error (导航误差)**：最终停下的位置距离目标的误差。

### 3. LLM-Assisted UAV Operations: Survey and Tutorial ([arXiv:2602.19534](https://arxiv.org/abs/2602.19534))
> **重点：这篇主要讲通信和系统层面的大模型应用，可以用来拓宽毕设的展望部分。**

*   **研究痛点 (解决什么问题)**：LLM 在实际部署到无人机边缘设备时受限于算力、功耗和通信带宽。
*   **设计建议**：在论文中探讨系统在 `sim`（仿真）和 `real_mocap`（实飞）模式下的通信延迟差异。

### 4. ALFRED: A Benchmark for Interpreting Grounded Instructions for Everyday Tasks (CVPR 2020)
> **重点：支撑任务完成率 (TCR) 和语义一致性分数 (SFS) 指标体系的核心依据。**

*   **研究痛点 (解决什么问题)**：过去的任务要么是纯导航，要么是纯语言，缺乏将“长视距指令跟随”与“具身物理交互”结合的复合型评估基准。
*   **核心贡献**：提出了多层级的评估指标体系。不仅有最终的 **Success Rate (SR)**（任务是否完成），还首次引入了 **Goal-Condition Success (GC)**（子目标达成率），允许对复杂任务进行部分计分。
*   **如何支撑毕设**：你的无人机实验指令包含“搜索-飞向-减速”等多阶段动作。ALFRED 的 GC 指标为你提出的 **语义一致性分数 (SFS)** 提供了直接的理论背书，证明了“分阶段/分条件评估”在具身智能评测中的学术正当性。
🔗 **论文网址**: [https://arxiv.org/abs/1912.01734](https://arxiv.org/abs/1912.01734)

### 5. On Evaluation of Embodied Navigation Agents (arXiv 2018)
> **重点：视觉语言导航（VLN）评测金标准，支撑兼顾效率的路径评测指标（SPL）。**

*   **研究痛点 (解决什么问题)**：在评估智能体导航时，仅看“是否到达终点（Success Rate）”是不够的，因为智能体可能会在环境中无序游走很久才偶然到达目标。
*   **核心贡献**：提出并确立了 **SPL (Success weighted by Path Length)** 指标。该指标要求智能体不仅要到达目标，还要走最短的有效路径。
*   **如何支撑毕设**：无人机的电池续航极其宝贵。在对比纯大模型和混合架构时，如果你的硬规则比纯大模型生成的冗长代码路径更短、耗时更少，你可以引用 SPL 思想（或转换为你的 Execution Efficiency / 耗时指标）来强有力地证明混合架构的高效性。
🔗 **论文网址**: [https://arxiv.org/abs/1807.06757](https://arxiv.org/abs/1807.06757)

### 6. Do As I Can, Not As I Say: Grounding Language in Robotic Affordances (arXiv 2022)
> **重点：SayCan 架构，将“规划成功率”与“物理执行成功率”分离评测的奠基作。**

*   **研究痛点 (解决什么问题)**：大语言模型（LLM）擅长高级推理，但不懂物理世界的限制（例如大模型计划让机器人“端起大象”，在文本逻辑上通顺，但物理上不可行）。
*   **核心贡献**：提出了将 LLM 的语义概率与机器人的物理可行性（Affordance）结合的架构。在评估时，明确区分了 **Plan Success Rate (规划成功率)** 和 **Execution Success Rate (执行成功率)**。
*   **如何支撑毕设**：你的系统恰好区分了 `parsing_success` (大模型代码生成成功) 和 `execution_success` (Mavlink 物理飞行成功)。引用 SayCan 可以完美解释你为什么要将这两者分开评估：大模型的输出（大脑）必须经过物理底层（小脑/硬规则）的校验后才能保证在三维世界中安全执行。
🔗 **论文网址**: [https://arxiv.org/abs/2204.01691](https://arxiv.org/abs/2204.01691)

### 需求 1：明确“故事线”与创新点

### 需求 2：执行对比实验（Ablation Study）
我们将设计一个**架构消融实验**：
*   **控制组（Baseline）**：所有的自然语言指令完全交给 LLM 翻译为 Python 代码去执行。
*   **实验组（你的代码）**：经过子句拆分，命中硬规则（如“急停”、“往前飞一点”）的直接绕过 LLM 执行。
*   **预期工作**：在你的 `test_eval_stats.py` 机制下，跑 30 个包含高频简单动作和复杂动作的用例，记录两者在 **任务总耗时（Duration）** 上的差异。

### 需求 3：执行模型横向对比实验
*   我们利用你的 `Config.json` 和 API 接口，分别接入 **GPT-4o（或 Claude-3.5）** 以及一个 **相对较弱的模型（如 GPT-3.5 或本地 Qwen）**。
*   **预期工作**：跑同样的一批测试集，得出不同模型下的 `chain_ok` (链路成功率)，证明你的系统可以通过接入更强的模型来无限拔高上限。
